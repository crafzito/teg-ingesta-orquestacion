0001: Workbook A4F: Ingeniería de Contexto para el Diseño de Sistemas Agénticos
0002: Versión: 2.1 (Iteración de Precisión)
0003: Audiencia: Equipo de Desarrollo LLM (A4F)
0004: Propósito: Estandarizar y aplicar nuestra metodología de Ingeniería de Contexto para construir, delegar y auditar sistemas agénticos de nivel de producción.
0005: 1. El Mindset A4F: De Asistente a Desarrollador SWE Asíncrono
0006: El primer cambio es de mentalidad. Abandonamos el uso de LLMs como meros asistentes para consultas "naif" (ej. "explícame este error").
0007: En A4F, tratamos a la IA como un Desarrollador de Software (SWE) Asíncrono. Nuestra tarea es conceptualizar y delegar desafíos técnicos completos (módulos, componentes de punta a punta) a un agente que opera con un contexto global híper-definido.
0008: Para entender por qué esto es un game-changer, usamos esta analogía:
0009: * El LLM (Large Language Model) es la CPU: El motor de razonamiento que maneja operaciones complejas.
0010: * La Ventana de Contexto es la RAM: La memoria volátil y de corto plazo con la que trabaja el LLM.
0011: * La Ingeniería de Contexto es el Sistema Operativo: Nuestra disciplina. Es el sistema que asegura que la información correcta y relevante (código, reglas, herramientas, memoria) esté cargada en la RAM en el momento preciso para que la CPU tome la mejor decisión.
0012: 2. Los 7 Pilares de la Ingeniería de Contexto
0013: Nuestra "Ingeniería de Contexto" consiste en gestionar activamente los 7 componentes que el agente "ve" en cada paso de un flujo:
0014: * User Prompt: El input inicial del usuario o del sistema que dispara la tarea.
0015: * Instructions / System Prompt: Las directrices globales y del proyecto (ver Patrón de 8 Puntos). Guían cómo procesar la información.
0016: * Long-Term Memory (Memoria a Largo Plazo): Datos persistentes útiles para tareas futuras (ej. Bases de datos vectoriales, RAG).
0017: * State / History (Memoria a Corto Plazo): El estado actual de la tarea. Mantiene los datos necesarios ahora (ej. "el usuario ya se autenticó").
0018: * Retrieved Information (RAG): Información específica recuperada de la memoria a largo plazo que es relevante para la decisión actual.
0019: * Available Tools (Herramientas Disponibles): Funciones, APIs y herramientas externas que el agente puede invocar para operaciones complejas.
0020: * Structured Output: La definición del formato de salida (ej. JSON, ZIP, XML) que el agente debe producir.
0021: 3. Arquitectura Operativa A4F: El Flujo Multi-LLM
0022: No usamos un solo LLM para todo. Asignamos roles basados en fortalezas para ejecutar la delegación:
0023: * El Arquitecto de Prompts (Gemini):
0024: * Misión: Tomar un Metaprompt (la solicitud de delegación inicial del desarrollador humano) y transformarlo en un Máster Prompt (la instrucción final, estructurada y lista para el agente).
0025: * Por qué: Usamos Gemini por su capacidad narrativa y su ventana de contexto masiva (1M tokens). Puede procesar el Metaprompt (que es más conversacional) junto con todo el código, las HUs, y los documentos adjuntos sin perder detalle, para generar el Máster Prompt estructurado de 8 puntos.
0026: * El Desarrollador Cirujano (GPT-5 Pro / Razonador):
0027: * Misión: Recibir el Máster Prompt (generado por Gemini) y ejecutar la tarea de desarrollo.
0028: * Por qué: Aunque su ventana de contexto es menor, su cualidad es desarrollar mejor el código. Es el "cirujano" que se enfoca en la tarea híper-definida. Su entregable es el artefacto de software (ej. un .zip).
0029: * El Auditor de Calidad (Modo Agéntico / Sandbox):
0030: * Misión: Recibir el artefacto (.zip) del "Cirujano", desplegarlo en un sandbox seguro, ejecutar pruebas, encontrar errores y proponer correcciones.
0031: * Implementación: Se logra con el "modo agéntico" de GPT-5 Pro, o mediante agentes SWE asincrónicos (LangGraph) o CLIs que pueden ejecutar código.
0032: 4. El Método A4F: La Estructura de 8 Puntos del Máster Prompt
0033: Para forzarnos a pensar como arquitectos, todo Metaprompt (la solicitud humana) es procesado por Gemini para generar un Máster Prompt (la delegación al Agente) que sigue esta estructura fundacional de 8 puntos:
0034: * Global System Prompt (GSP): Nuestros parámetros y patrones como empresa (A4F) para desarrollar software (calidad, seguridad, FinOps).
0035: * Project System Prompt (PSP): Los parámetros específicos del proyecto (stack tecnológico, repositorios, contexto de negocio).
0036: * Open Source projects reference: Links a repositorios (MIT/Apache) que sirvan como inspiración o estándar.
0037: * Key Papers: Artículos (Arxiv.org, 2023+) que provean el marco teórico o conceptual.
0038: * Example: Un ejemplo de código concreto que ilustra el patrón de diseño o la lógica deseada.
0039: * Previous Code: El código existente, documentos adjuntos, HUs, o cualquier contexto previo relevante.
0040: * Challenge Prompt: La definición explícita del problema, los componentes a desarrollar, el foco de valor y las restricciones.
0041: * Bases para futuras evoluciones (V2.0): Pistas sobre cómo la solución debe escalar o evolucionar.
